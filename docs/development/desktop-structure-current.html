Architecture · bin-desktop · as of 2026-10-08 · issue #551

Desktop app: current module structure

  • One Entity owns everything. Shell is the only impl Render root of substance and holds nav state, toasts, palette, dialogs, every Settings field and the domain data (accounts, categories, budgets, …) as plain fields. shell.rs alone is ~10.3k lines.
  • Views and Chrome are render functions over &Shell, not their own Entities; the Chrome also reaches straight into domain modules (budgets, documents, bills) for rail context.
  • Domain modules are already gpui-free (no use gpui in accounts, bills, budgets, categories, documents, inventory, payees, tags, transactions) and serve seeded mock data: a clean seam for a later service layer.
  • Persistent state today is UI-only: persistence.rs writes noun, rail mode and window geometry to desktop-state.json. lib_database is a dependency but nothing queries it yet.
