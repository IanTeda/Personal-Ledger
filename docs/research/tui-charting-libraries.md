# Research: Rust TUI libraries for charts and tables

**Question.** `docs/product-requirements.md` §2.1 sets out FC-TUI-001 (research Rust TUI libraries and lock the choice in a later ADR — not this document), FC-TUI-002 (demonstrate line, doughnut, candlestick, and divergent/diverging-bar charts working in the planned TUI app across Linux, macOS, and Windows terminals, using dummy data), and FC-TUI-003 (demonstrate tables work in the TUI app across the same platforms). This note is primary-source research only, feeding the later decision ticket (#11, "Decide TUI library and record ADR"). It does not recommend or decide anything. All claims are cited to primary sources — crates.io (including its JSON API, `https://crates.io/api/v1/crates/<name>`, used where the HTML search/crate pages render via client-side JavaScript and don't expose data to a plain fetch), docs.rs API docs, official GitHub repositories (README, source, issue tracker, `Cargo.toml`), and the GitHub REST API (`api.github.com`) for issue/star/contributor counts and last-push timestamps — not blog posts, Reddit, or third-party tutorials. Research was carried out on 2026-09-01; version numbers, download counts, and issue counts are a snapshot as of that date and will drift.

## 1. `ratatui`

**Identity and maintenance.** `ratatui` is "a Rust crate for cooking up terminal user interfaces (TUIs)" and is a fork of the now-archived `tui-rs` (GitHub repo description, https://github.com/ratatui/ratatui). Per the crates.io JSON API (https://crates.io/api/v1/crates/ratatui), the newest published version as of this research is **0.30.2**, first created 2023-02-08, last updated 2026-06-19, MIT-licensed, with 47,597,664 total downloads. The GitHub REST API (`api.github.com/repos/ratatui/ratatui`) reports 22,461 stars, 760 forks, and 225 open issues as of 2026-09-01; a `contributors?per_page=1&anon=true` pagination probe returns a `last` page of 295, indicating roughly 295 contributors (including anonymous/squashed commits) — an approximate figure derived from GitHub's `Link` header pagination, not an exact count the API exposes directly.

**`Chart` widget.** docs.rs (https://docs.rs/ratatui/latest/ratatui/widgets/struct.Chart.html) describes `Chart` as "a widget to plot one or more `Dataset` in a cartesian coordinate system." Each `Dataset` carries a `GraphType`, and the documented example code uses `GraphType::Line` (Braille marker) and `GraphType::Scatter` (Dot marker) — i.e. natively `Chart` covers **line and scatter** plots only, with configurable axis titles/bounds/labels, per-dataset styling, and a positionable legend. There is no native pie/doughnut, candlestick, or diverging-bar graph type on `Chart` itself.

**`Canvas` widget.** docs.rs (https://docs.rs/ratatui/latest/ratatui/widgets/canvas/index.html) describes `Canvas` as providing "a means to draw shapes (Lines, Rectangles, Circles, etc.) on a grid" — "a blank space on which you can draw anything manually or use one of the predefined Shapes." The built-in shape primitives documented in the `canvas` module are: `Circle`, `Line`, `FilledLine` (fills the area to a given y-coordinate), `Rectangle`, `Points`, `Map` (an EPSG:4326 world map), and `Label` (text drawn on the canvas), plus a documented extension point ("you can also implement your own custom `Shapes`") backed by a `Painter`/`Context` abstraction. This is the primitive layer any custom doughnut or candlestick renderer would be built on if no ready-made widget crate is used.

**`BarChart` widget.** docs.rs (https://docs.rs/ratatui/latest/ratatui/widgets/struct.BarChart.html) confirms `BarChart` supports grouped bars via `BarGroup`/`Bar`, and both vertical/horizontal orientation via `direction()`. The bar value type is `u64` throughout the documented API and examples show bars extending from a single baseline in one direction — **no documented support for negative values or two-directional/diverging bars** was found on this widget.

**`Sparkline` widget.** docs.rs (https://docs.rs/ratatui/latest/ratatui/widgets/struct.Sparkline.html): renders a compact single-line bar visualisation from `u64`/`Option<u64>`/`SparklineBar` data, with configurable direction, bar-set glyph density (three or nine levels), and explicit styling for absent (`None`) values. It is single-dimension only — not relevant to doughnut/candlestick/diverging needs beyond being another Canvas-adjacent primitive.

**`Table` widget.** docs.rs (https://docs.rs/ratatui/latest/ratatui/widgets/struct.Table.html): supports row/column/cell selection and highlighting via `TableState` (with highlight-style precedence Row → Column → Cell), auto-scrolls to keep a selected row visible, configurable column widths via a constraint system (`.widths()`; omitting it renders all columns at width 0), and optional always-visible header/footer rows. **No built-in sorting** is documented — the docs make no mention of a sort method or trait; sorting would need to be done by the application before handing rows to the widget.

**Backends and Windows support.** The crate-level docs (https://docs.rs/ratatui/latest/ratatui/) state: "By default, we enable the crossterm backend as this is a reasonable choice for most applications as it is supported on Linux/Mac/Windows systems." docs.rs's backend module index (https://docs.rs/ratatui/latest/ratatui/backend/index.html) lists four real backend implementations — `CrosstermBackend`, `TermionBackend`, `TermwizBackend`, and a `TerminaBackend` (via the `termina` crate) — plus a `TestBackend` for headless/in-memory rendering. `TermionBackend` is explicitly gated `#[cfg(all(feature = "termion", not(target_os = "windows")))]` per the docs' own platform annotation, i.e. **termion is excluded on Windows** by ratatui's own conditional compilation. This is corroborated independently by termion's own README (https://github.com/redox-os/termion): "Supports Redox, Mac OS X, BSD, and Linux (or, in general, ANSI terminals)" — Windows is not listed. Crossterm is therefore the only ratatui backend documented as covering all three target platforms (Linux/macOS/Windows) from a single backend choice.

**Ecosystem — chart-type-specific extension crates.** Searching crates.io and the community-curated `awesome-ratatui` list (https://github.com/ratatui/awesome-ratatui) found:

- **Doughnut/pie:** `tui-piechart` (https://crates.io/crates/tui-piechart, https://github.com/sorinirimies/tui-piechart) — "a customizable pie chart widget for Ratatui TUI applications," version 1.0.2, MIT, created 2025-11-08 and pushed 2026-08-21 per the GitHub API (`open_issues_count: 0`), i.e. recently active. Its README lists "simple pie chart with customizable slices" and a "high resolution mode using braille patterns," but **does not mention a doughnut/ring (hollow-centre) variant** — only solid pie is documented; the underlying implementation approach (whether it sits on `Canvas`) is not stated in the README.
- **Candlestick:** `chandelier` (https://crates.io/crates/chandelier, https://github.com/jonathan-g-davis/chandelier) — "financial charting widgets for Ratatui," version 0.4.0, dual MIT/Apache-2.0, created 2026-05-31, GitHub `pushed_at` 2026-07-13 with 2 open issues — i.e. a very young (roughly three months old at time of writing), small crate (217 total crates.io downloads). Its README states a chart is "a `CandleSeries` (the bars and how they are coloured) drawn by a `CandlestickChart`," and that `CandlestickChart` "implements `Widget`, so render it like any other Ratatui widget" — it does not describe itself as built on `Canvas`, and appears purpose-built for candlesticks specifically (no line/volume chart types documented).
- Also found but not ratatui-specific: `cli-candlestick-chart` (https://crates.io/crates/cli-candlestick-chart, https://github.com/Julien-R44/cli-candlestick-chart) — "a library for displaying candlestick charts right into your terminal," MIT, last published to crates.io 2021-12-14 (over four and a half years stale as of this research); its README describes it as shippable "as library" or "as binary for standalone usage," and no ratatui/crossterm dependency was confirmed from the available README/Cargo.toml excerpt — it reads as an independent terminal renderer rather than a ratatui widget.
- **Diverging/divergent bars:** no crate was found. A crates.io JSON search for `"diverging bar"` (https://crates.io/api/v1/crates?q=diverging%20bar`) returned no TUI/charting results at all (unrelated crates such as a Perl interpreter and dataframe libraries). A broader search for `"ratatui chart"` on crates.io surfaced no crate whose name or description mentions diverging/divergent bars; the closest ratatui-ecosystem hits were `ratatui-stacked-bar` (stacked area/bar chart, not diverging), and reserved/placeholder-looking names (`ratatui-chart`, `ratatui-bar-chart`, `ratatui-barchart`, `ratatui-visuals`, `ratatui-tree-map` — crates.io descriptions of "Reserved for ..." suggest these are unpublished namespace reservations, not working crates). **As of 2026-09-01, no crate matching "diverging"/"divergent" bar charts for ratatui (or standalone) was found on crates.io.**
- Other adjacent finds: `malevich` (https://crates.io/crates/malevich, https://github.com/shergin/malevich) — "terminal plotting: a small grammar of marks, honest axes, millions of points," version 1.20.0, dual MIT/Apache-2.0, created 2026-08-02 (i.e. under a month old at research time), with an optional (non-default) `ratatui` feature. Its description advertises "line, scatter, bar, histogram, heatmap, box plot, violin, and more" (per the `awesome-ratatui` list entry) — no pie/doughnut or candlestick chart type is mentioned, so it does not close either gap, though its bar-plot support may be adjacent to diverging-bar needs if extended.
- Financial TUI *applications* that render candlesticks internally (not reusable widget crates) were also found via `awesome-ratatui`: `alphai-tui` (stock dashboard with candlestick charts, https://github.com/makeev/alphai-tui) and `tickrs` (stock ticker, https://github.com/tarkah/tickrs) — these demonstrate the pattern is achievable on ratatui but aren't extractable dependencies per se.

**Summary for §4 framing:** doughnut charts need either a hollow-centre extension to `tui-piechart` (which is solid-pie only) or custom `Canvas` work (`Circle`/`Points` primitives). Candlestick charts have one small, very new (~3-month-old) dedicated crate (`chandelier`) or otherwise need custom `Canvas` work. Diverging/divergent bars have no dedicated crate found at all and would need either custom `Canvas` work or building on top of `BarChart`/`Chart` primitives (e.g. plotting positive and negative `Bar`/`Dataset` values manually, since `BarChart`'s `u64` values don't natively support negative extents).

## 2. `cursive`

**Identity and maintenance.** Per crates.io's JSON API (https://crates.io/api/v1/crates/cursive), `cursive` is "a TUI (Text User Interface) library focused on ease-of-use," newest version **0.21.1**, MIT-licensed, created 2016-06-25, and **last published 2024-08-03** — over two years stale relative to this research date (2026-09-01). The GitHub API (`api.github.com/repos/gyscos/cursive`) shows `pushed_at: 2026-08-01`, 4,843 stars, 268 forks, and 216 open issues — so there has been recent repository push activity even though the crates.io package itself hasn't had a new release in two years; this split (active repo, stale published crate) is worth flagging explicitly since it affects what a `cargo add cursive` actually pulls in today.

**Charting.** No mention of any charting or plotting widget was found in the GitHub repo's description or its listed extension views (calendar, hex viewer, tree, table, tabs) — cursive is oriented around dialogs/forms/menus rather than data visualisation, and no built-in `Chart`/`Canvas`-equivalent was found in `cursive_core` or the main crate's own widget set.

**Table widget.** Table support in the cursive ecosystem is a third-party crate, `cursive_table_view` (https://crates.io/crates/cursive_table_view, https://github.com/BonsaiDen/cursive_table_view) — "a basic table view implementation for cursive," version 0.15.0, dual MIT/Apache-2.0. docs.rs (https://docs.rs/cursive_table_view/latest/cursive_table_view/) documents `TableView` as a "view to select an item among a list, supporting multiple columns for sorting," with a `TableViewItem` trait described as "a trait for displaying and sorting items inside a `TableView`" — i.e. **column sorting is supported**, unlike ratatui's `Table`. Maintenance is a concern: the GitHub API shows `pushed_at: 2024-08-02` — also roughly two years stale as of this research — with 15 open issues.

**Backends and Windows support.** `cursive`'s own `Cargo.toml` (fetched from https://raw.githubusercontent.com/gyscos/cursive/main/cursive/Cargo.toml) defines five backend features: `crossterm-backend` (crossterm 0.29.0, the default), `ncurses-backend` (`ncurses` 6.0.1), `pancurses-backend` (`pancurses` 0.17), `termion-backend` (`termion` 4), and `blt-backend` (`bear-lib-terminal` 2, requiring a separately-installed native BearLibTerminal library). The project's GitHub wiki (https://github.com/gyscos/cursive/wiki/Backends) states platform support per backend explicitly:

- **crossterm** — "works crossplatform, even for windows systems down to version 7." (Windows: yes)
- **ncurses** — "currently only compatible on Linux and macOS." (Windows: no)
- **pancurses** — "forwards calls to ncurses-rs on Linux/macOS or pdcurses-sys on Windows." (Windows: yes)
- **termion** — "works on Linux, macOS, and Redox." (Windows: no)
- **BearLibTerminal (blt)** — "cross-platform BearLibTerminal.rs binding. Works on Linux and Windows." (Windows: yes, but needs the external native library installed)

As with ratatui, crossterm is the one backend that is both the crate's own default and confirmed cross-platform across all three target platforms without an extra native dependency.

## 3. Other actively maintained alternatives

- **`tui-rs`** (the project ratatui forked from) — **confirmed unmaintained/archived.** The GitHub repo (https://github.com/fdehau/tui-rs) shows GitHub's own archive banner, "This repository was archived by the owner on Aug 6, 2023. It is now read-only," and the README's own top-of-file notice reads: "⚠️ August 2023: This crate is no longer maintained. See https://github.com/ratatui-org/ratatui for an actively maintained fork. ⚠️" crates.io (https://crates.io/api/v1/crates/tui) shows its newest version 0.19.0 was last published 2022-08-14. This confirms the CLAUDE.md-adjacent assumption that `tui-rs` and `ratatui` are easily confused but only the latter is live; anyone finding `tui-rs` tutorials/examples should treat them as historical.
- **`termwiz`** (https://crates.io/crates/termwiz, part of the `wezterm` project, https://github.com/wezterm/wezterm) — "Terminal Wizardry for Unix and Windows," version 0.23.3, MIT, 20+ million total downloads, last published 2025-03-20. It is also one of ratatui's own supported backend crates (`TermwizBackend`, §1) rather than purely a competing framework — it's lower-level terminal-handling machinery (wezterm's own terminal engine) that can be used standalone or as a ratatui backend. No dedicated charting layer was surveyed for it beyond its role as a ratatui backend; it wasn't evaluated further as a full alternative TUI *framework* to ratatui/cursive since its primary identity is a terminal I/O layer.
- **`iocraft`** (https://crates.io/crates/iocraft, https://github.com/ccbrown/iocraft) — "a Rust crate for beautiful, artisanally crafted CLIs and TUIs" using flexbox layout (via `taffy`) and a React-like declarative component API (in contrast to ratatui's immediate-mode style). GitHub API shows `pushed_at: 2026-08-20`, 1,529 stars, 28 open issues — actively maintained and recently pushed. Dual Apache-2.0/MIT licensed. Its README explicitly claims "broad support for both Unix and Windows terminals," with a PowerShell-labelled example screenshot corroborating Windows support. **No chart widgets were found** — the documented built-in components are `View`, `Text`, and `TextInput`, with example code showing tables and progress bars but no line/pie/candlestick/bar chart primitives; any charting on iocraft would be fully custom (it doesn't even have a documented `Canvas`-equivalent low-level drawing primitive the way ratatui does).
- Categories browsed on crates.io ("command-line-interface") did not surface any other genuinely-maintained full TUI *framework* beyond the above (`zellij` is a terminal multiplexer application, not a library/framework for building TUI apps, and was excluded per the task's own scoping note).

## 4. Comparison summary

This table surfaces trade-offs only; it does not recommend a choice — that is deliberately left to ticket #11's ADR.

| Criterion | `ratatui` | `cursive` | `iocraft` |
|---|---|---|---|
| Latest version / last publish | 0.30.2 / 2026-06-19 (crates.io) | 0.21.1 / 2024-08-03 (crates.io) — repo `pushed_at` 2026-08-01 | 0.8.4 / 2026-07-13 (per crates.io per WebSearch) — repo `pushed_at` 2026-08-20 |
| Licence | MIT | MIT | Apache-2.0 OR MIT |
| GitHub stars / open issues | 22,461 / 225 | 4,843 / 216 | 1,529 / 28 |
| Native line/scatter chart | `Chart` widget (`GraphType::Line`/`Scatter`) | none found | none found |
| Native bar chart | `BarChart` (grouped, `u64`-only, no documented negative/diverging support) | none found | none found |
| Native table | `Table` (selection, scrolling, styling; **no built-in sort**) | none in core; `cursive_table_view` (3rd-party, **sorting supported**, but crates.io publish and GitHub push both stale since Aug 2024) | none found in README |

Sources for every claim above are cited inline in §1–3; no claim in this table is asserted without a citation given earlier in this document.
