# Research: How the shipped packages carry the licence and third-party notices

**Question.** GitHub issue #610 (part of #605) asks how the shipped packages should carry Personal Ledger's MIT licence and the third-party notices their dependencies require. The packages are the Sync Server image (`Dockerfile.sync-server`), the Desktop installers (NSIS, dmg and AppImage via cargo-packager) and the TUI packages (AppImage, dmg, plus the hand-rolled Windows zip from ADR-0004). It asks which notice duties the built dependency graph actually carries, which generator fits, where the files go in each package, and whether notices are generated in CI or checked in. The relicensing decision is already made: the project is plain MIT (root `LICENSE`, `[workspace.package] license = "MIT"`, ADR-0036). This follows up `docs/research/project-licence.md` §4, §9 step 7 and the two §10 items on notices. Sources are the licence texts (SPDX `license-list-data`, apache.org, mozilla.org), the cargo-about, cargo-bundle-licenses, cargo-deny and cargo-packager docs and source, the OCI image spec, Debian Policy, and this repository's own files plus `cargo tree`, `cargo metadata` and a local cargo-about trial. Research was carried out on 2026-10-10 against the `concept` branch at `2da7040`; the dependency graph is a snapshot of `Cargo.lock` at that commit and will drift. This is not legal advice.

## 1. Current state in this repository

- **Root `LICENSE`** is the MIT text with "Copyright (c) 2024–2026 Ian Teda". Every crate inherits `license = "MIT"` from `[workspace.package]`.
- **Sync Server image.** `.dockerignore` lists `LICENSE*` (and `*.md`, `docs/`) under "Docs and non-build metadata", so the builder stage never sees the licence. The runtime stage of `Dockerfile.sync-server` copies only `/usr/local/bin/sync-server` and the entrypoint script. The image published to GHCR by `.github/workflows/build-publish-sync-server.yaml` carries neither Personal Ledger's licence nor any third-party notice, and sets no `org.opencontainers.image.licenses` label.
- **Desktop and TUI packages.** `[package.metadata.packager]` in `crates/bins/bin-desktop/Cargo.toml` and `crates/bins/bin-tui/Cargo.toml` sets `product-name`, `identifier`, `formats`, `icons` and `binaries`, but no `license_file`, `copyright` or `resources`. CI pins cargo-packager `0.11.8` (`CARGO_PACKAGER_VERSION` in `build-publish-desktop.yaml` and `build-publish-tui.yaml`). The Desktop workflow packages NSIS on Windows and dmg on macOS; the TUI workflow packages AppImage on Linux and dmg on macOS, and zips the bare `personal-ledger-tui.exe` on Windows with `Compress-Archive`. None of these carries a licence or notices file.
- **Bundled non-Cargo assets.** `bin-desktop` embeds the Archivo fonts with `include_bytes!` (`crates/bins/bin-desktop/src/lib.rs`, licence `assets/fonts/OFL.txt`, "Copyright 2020 The Archivo Project Authors", SIL OFL 1.1) and the Lucide icons (`src/assets/mod.rs`, licence `assets/icons/LICENSE`, ISC "Copyright (c) 2026 Lucide Icons and Contributors" with a Feather-derived MIT portion). A Cargo-based generator cannot see these, because they are files, not crates.
- **`deny.toml`** allows `0BSD`, `Apache-2.0`, `Apache-2.0 WITH LLVM-exception`, `BSD-1-Clause`, `BSD-2-Clause`, `BSD-3-Clause`, `BSL-1.0`, `CC0-1.0`, `CDLA-Permissive-2.0`, `ISC`, `MIT`, `MIT-0`, `MPL-2.0`, `NCSA`, `Unicode-3.0`, `Unlicense` and `Zlib`, with `[graph] all-features = true` and `[licenses.private] ignore = true`. cargo-deny is pinned in `mise.toml` (`cargo-deny = "0.20.2"`, which mise resolves to `aqua:EmbarkStudios/cargo-deny`) and run by `lint-main-push.yaml`.
- **No packaging step collects notices today**, which `project-licence.md` §4 and §10 already flagged.

## 2. What the built graph actually contains

**Method.** For each bin, `SQLX_OFFLINE=true mise exec -- cargo tree --offline --locked -p <bin> -e normal,no-proc-macro --target all --prefix none --format '{p}|{l}'`, deduplicated, with workspace crates removed. `-e normal,no-proc-macro` drops build-, dev- and proc-macro-only crates, which are not linked into the binary; `--target all` keeps every platform's `cfg` dependencies, so it slightly over-counts any one package (for example Windows-only crates in the Linux AppImage). Each crate's directory under `~/.cargo/registry/src/` was then checked for `NOTICE*` and licence files via `cargo metadata`.

**Size.** The Sync Server links 325 registry packages, the Desktop 738 and the TUI 337 (1,086 distinct name-version pairs across all three).

**Packages whose expression MIT alone cannot satisfy.** Most crates are `MIT`, `MIT OR Apache-2.0` or another `OR` that includes MIT. Those that are not:

- **Unicode-3.0**: the ICU4X family (`icu_*`, `fixed_decimal`, `ixdtf`, `litemap`, `potential_utf`, `tinystr`, `writeable`, `yoke`, `zerofrom`, `zerotrie`, `zerovec`) behind `lib-locale`, in all three bins (the Sync Server gets a smaller set through URL/IDNA handling). `unicode-ident` is `(MIT OR Apache-2.0) AND Unicode-3.0`, so it always needs the Unicode text too.
- **Apache-2.0 only**: `prost`, `prost-types`, `sync_wrapper` (Sync Server); `gpui` and every `gpui_*` crate, `gpui-component`, `zed-sum-tree`, `calendrical_calculations`, `codespan-reporting`, `command-fds`, `gethostname`, `spirv`, `stacksafe`, `unicode-linebreak` (Desktop); `calendrical_calculations` (TUI). `ring` is `Apache-2.0 AND ISC` in all three.
- **BSD-3-Clause**: `subtle`, `sha1_smol`, `deunicode` (all three), `curve25519-dalek`, `ed25519-dalek` (Sync Server), and image and rendering crates in the Desktop (`tiny-skia`, `tiny-skia-path`, `exr`, `lebe`, `ravif`, `avif-serialize`, `instant`). `matchit` is `MIT AND BSD-3-Clause` and `encoding_rs` is `(Apache-2.0 OR MIT) AND BSD-3-Clause`.
- **BSD-2-Clause**: `arrayref`, `av1-grain`, `rav1e`, `v_frame` (Desktop only).
- **ISC**: `rustls-webpki`, `untrusted`, `json5` (all three), plus `inotify`, `inotify-sys`, `libloading` (Desktop).
- **MPL-2.0**: `option-ext 0.2.0` (all three, via `dirs-sys` ← `dirs`) and `dwrote 0.11.5` (Desktop, Windows only: `[target.'cfg(target_family = "windows")'.dependencies.dwrote]` in `zed-font-kit-0.14.1-zed/Cargo.toml`).
- **CDLA-Permissive-2.0**: `webpki-roots 0.26.11` and `1.0.9` (all three), the bundled Mozilla CA root data.
- **Zlib**: `foldhash` (all three), `nanorand`, `slotmap` (Desktop).
- **No-attribution licences**: `ryu` (`Apache-2.0 OR BSL-1.0`), `notify`, `hexf-parse` (CC0-1.0), `enum-iterator` (0BSD), `dunce`, `imgref` (CC0 options).
- **Choice expressions with a copyleft option**: `self_cell` (`Apache-2.0 OR GPL-2.0-only`, Desktop and TUI) and `r-efi` (`MIT OR Apache-2.0 OR LGPL-2.1-or-later`); the permissive option applies.
- **NCSA**: `libfuzzer-sys` (`(MIT OR Apache-2.0) AND NCSA`) shows up under `cargo tree --target all` for the Desktop, but cargo-about, filtered to the four real targets, did not include it (§4), so it is not in a shipped binary.

**NOTICE files.** None of the shipped crates' published directories contains a `NOTICE*` file. (`cfg_aliases`, the one crate `project-licence.md` §4 found with a `NOTICE`, is build-time only and drops out with `-e normal`.) So the Apache-2.0 §4(d) NOTICE duty is currently empty. That is a fact about the published `.crate` contents only: whether any upstream repository has a NOTICE file that was left out of the published crate was not checked.

**Crates without a licence file.** 55 shipped crates publish no `LICENSE`/`COPYING` file at all, only the `license` field. Examples: `objc2`, `objc2-foundation`, `taffy`, `tree-sitter`, `naga`, the `lyon_*` crates, `blade-graphics`, `pathfinder_geometry`, `tonic-prost`, `rust-i18n-support`, `spirv`, `stacksafe` and `dwrote`. For these, any generator can only reproduce the canonical licence text, without the author's copyright line.

## 3. What each licence requires of a binary distribution

| Licence | Duty when shipping a binary | Source |
| --- | --- | --- |
| MIT (incl. Personal Ledger's own) | "The above copyright notice and this permission notice shall be included in all copies or substantial portions of the Software." | https://opensource.org/license/mit |
| ISC | The copyright notice and permission notice must "appear in all copies". | https://spdx.org/licenses/ISC.html |
| BSD-2-Clause / BSD-3-Clause | "Redistributions in binary form must reproduce the above copyright notice, this list of conditions and the following disclaimer in the documentation and/or other materials provided with the distribution." | https://spdx.org/licenses/BSD-3-Clause.html |
| Apache-2.0 | §4(a) give recipients "a copy of this License"; §4(d) if the Work includes a `NOTICE` file, include its attribution notices "within a NOTICE text file distributed as part of the Derivative Works", in the documentation, or "within a display generated by the Derivative Works". | https://www.apache.org/licenses/LICENSE-2.0.txt |
| Unicode-3.0 | "this copyright and permission notice appear with all copies of the Data Files or Software" (or in associated documentation). | https://spdx.org/licenses/Unicode-3.0.html |
| MPL-2.0 | §3.2(a) the Covered Software "must also be made available in Source Code Form" and "You must inform recipients of the Executable Form how they can obtain a copy of such Source Code Form"; §3.2(b) the binary may be sublicensed under other terms that don't limit recipients' rights in the source. Only the MPL files themselves are covered, and they are unmodified here. | https://www.mozilla.org/en-US/MPL/2.0/ |
| CDLA-Permissive-2.0 | §2.1 a Data Recipient may share Data "so long as the Data Recipient makes available the text of this agreement with the shared Data". | https://cdla.dev/permissive-2-0/ |
| Zlib | "This notice may not be removed or altered from any source distribution." Nothing is required for binaries (acknowledgement "would be appreciated but is not required"). | https://spdx.org/licenses/Zlib.html |
| BSL-1.0 | Notices must be included "unless such copies or derivative works are solely in the form of machine-executable object code generated by a source language processor", so nothing is required for a binary. | https://www.boost.org/LICENSE_1_0.txt |
| CC0-1.0, 0BSD, MIT-0, Unlicense | No attribution duty. | https://spdx.org/licenses/ |
| SIL OFL 1.1 (Archivo) | §2 fonts "may be bundled ... with any software, provided that each copy contains the above copyright notice and this license", as "stand-alone text files, human-readable headers or in the appropriate machine-readable metadata fields". §5 the fonts stay under the OFL. | https://openfontlicense.org/open-font-license-official-text/ |

**Net duties for the packages:**

1. Ship Personal Ledger's own `LICENSE` (MIT) in every package.
2. Ship one third-party notices file per package with the licence text and copyright lines of every linked crate under MIT, ISC, BSD, Apache-2.0, Unicode-3.0 and CDLA-Permissive-2.0. Zlib, BSL-1.0 and the public-domain-style licences are optional to include, but harmless.
3. For `option-ext` and `dwrote`, state where the MPL source is. A crates.io URL or the upstream repository (`https://github.com/soc/option-ext`, `https://github.com/servo/dwrote-rs`) satisfies "by reasonable means", since the source is publicly available and unmodified (MPL-2.0 §3.2(a)).
4. Ship `OFL.txt` and the Lucide `LICENSE` with the Desktop packages, since the fonts and icons are compiled into the binary.
5. No Apache NOTICE content to carry today, but the generator should pick it up if a future crate ships one.

Choosing MIT over Apache-2.0 for the many `MIT OR Apache-2.0` crates matters for size: it keeps the Apache text to the few Apache-only crates and avoids the §4(d) NOTICE duty for crates that offer a choice.

## 4. Generators

**cargo-about** (https://github.com/EmbarkStudios/cargo-about, docs https://embarkstudios.github.io/cargo-about/).

- **Maintenance.** Embark Studios, Apache-2.0 OR MIT, 796 stars, not archived. Latest release `0.9.2` on 2026-08-18, last push 2026-09-18 (GitHub API). Its CHANGELOG shows steady releases (0.8.0 September 2025 through 0.9.2). It shares maintainers and the `spdx` crate with cargo-deny, which this repo already uses.
- **OR expressions.** The `accepted` list is a priority list: "cargo-about will try to satisfy the licenses in the order that they are declared in this list ... if a crate is licensed with the typical `Apache-2.0 OR MIT` license expression, only the `Apache-2.0` license would be used as it has higher priority" (docs, `generate/config.md`). `AND` expressions require every term, and per-crate `accepted` entries and `clarify` blocks with SHA-256-checked source files handle odd cases. Built-in `workarounds` cover crates in this graph (`ring`, `rustls`, `prost`).
- **deny.toml reuse.** None. cargo-about reads its own `about.toml` (`-c`, defaulting to `<manifest_root>/about.toml`), and a search of the repository finds no reference to `deny.toml`. The `accepted` list has to be maintained by hand alongside `deny.toml`'s `allow`. It can be the same set, but ordered with MIT first, whereas cargo-deny's list is unordered.
- **Output.** Handlebars templates, or `--format json`. Templates get `overview` (licence, count) and `licenses` (name, SPDX id, full `text`, `source_path`, and `used_by`, each holding a `cargo_metadata::Package`, so `crate.repository` is available for the MPL source pointer). HTML is the default (`about.hbs`), and a plain-text template works as long as it uses triple braces (`{{{text}}}`), because `{{text}}` HTML-escapes quotes.
- **Scope controls.** `targets` filters `cfg()` dependencies to the platforms actually built. `ignore-build-dependencies`, `ignore-dev-dependencies` and `private = { ignore = true }` skip the unpublished workspace crates. `--manifest-path` selects one bin; `--workspace` scans everything. `--fail` exits non-zero "if any crate's license cannot be reasonably determined", which makes it usable as a CI gate. `--offline`/`--locked` work, though offline mode skips git-sourced clarifications and falls back to the canonical licence text.
- **Install.** Prebuilt release archives exist for `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`, `aarch64-apple-darwin`, `x86_64-pc-windows-msvc` and `aarch64-pc-windows-msvc`, with `.sha256` files (GitHub releases API, `0.9.2`); there is no `x86_64-apple-darwin` archive. cargo-about is not in mise's registry (`mise registry cargo-about` errors), unlike cargo-deny. **Gotcha:** since 0.9.0 the binary has `required-features = ["cli"]` and `cli` is not a default feature (`cargo-about-0.9.2/Cargo.toml`), so the README's `cargo install --locked cargo-about` builds the library and installs nothing ("none of the package's binaries are available for install using the selected features"). It needs `--features cli`.

**Trial.** cargo-about `0.9.2` was installed with `cargo install --locked --features cli --root "$TMPDIR/tools"` (and a temporary `CARGO_HOME`, because `~/.cargo/registry` is read-only in this sandbox). It was then run per bin with `generate --fail --offline --locked --manifest-path crates/bins/bin-<name>/Cargo.toml`. The config used `accepted` = the `deny.toml` allow set ordered `MIT, ISC, 0BSD, MIT-0, Unlicense, CC0-1.0, BSD-*, Zlib, BSL-1.0, Apache-2.0, Apache-2.0 WITH LLVM-exception, Unicode-3.0, CDLA-Permissive-2.0, MPL-2.0, NCSA`, plus `ignore-build-dependencies`, `ignore-dev-dependencies`, `private.ignore`, `workarounds = ["ring", "rustls", "prost"]`, and `targets` set to the shipped platforms. All three succeeded with `--fail`, in about 25 seconds each:

- **Sync Server** (Linux x86_64 and aarch64): MIT 283, ISC 19, Unicode-3.0 19, BSD-3-Clause 8, Apache-2.0 6, CDLA-Permissive-2.0 2, Zlib 2, BSL-1.0 1, CC0-1.0 1, MPL-2.0 1. About 270 KB of text.
- **Desktop** (Linux, Windows, both macOS): MIT 694, Unicode-3.0 42, BSD-3-Clause 41, Apache-2.0 26, ISC 22, BSD-2-Clause 5, CC0-1.0 5, Zlib 5, 0BSD 2, CDLA-Permissive-2.0 2, MPL-2.0 2 (`dwrote`, `option-ext`), BSL-1.0 1, MIT-0 1. About 595 KB.
- **TUI**: MIT 295, Unicode-3.0 42, ISC 19, BSD-3-Clause 5, Apache-2.0 4, CDLA-Permissive-2.0 2, Zlib 2, BSL-1.0 1, CC0-1.0 1, MPL-2.0 1. About 268 KB.

cargo-about's counts include some proc-macro crates (`gpui-macros`, `prost-derive`, `yoke-derive`), which over-includes harmlessly. Crates with no licence file (`dwrote`, `tonic-prost`, …) came out with the canonical SPDX text rather than failing.

**cargo-bundle-licenses** (https://github.com/sstadick/cargo-bundle-licenses).

- **Maintenance.** One maintainer, Apache-2.0, 113 stars. Latest release `v4.2.0` on 2025-10-21, last commit 2026-08-19.
- **OR expressions.** It does not choose. `process_spdx_expression` in `src/license.rs` walks the expression and "ignor[es] operators as we just need a list of used licenses and not how they are combined", so a `MIT OR Apache-2.0` crate is recorded under both licences.
- **deny.toml reuse.** None, and it has no allow list at all.
- **Output.** `json`, `yaml` or `toml` only; the README says a "more human readable format ... is being actively sought". Its intended workflow is a checked-in `THIRDPARTY.yml` patched by hand for licences it can't find, with CI running `--previous THIRDPARTY.yml --check-previous` to fail on drift.
- **Fit.** Poor. The output is not something to put in front of an end user without another rendering step, and it skips the `OR` choice that keeps the notices small.

**cargo-deny `list`** (https://embarkstudios.github.io/cargo-deny/cli/list.html) prints licence identifiers per crate or per licence in `human`, `json` or `tsv`. It emits no licence texts or copyright lines, so it cannot produce a notices file. It stays useful as the policy gate it already is.

**cargo-license** lists only the `license` fields from `Cargo.toml` (as the cargo-bundle-licenses README also notes), so it fails the same way.

**Verdict.** cargo-about is the only one of these that produces an end-user notices file, resolves `OR` choices, gates on unknown licences, and is actively maintained by the cargo-deny authors.

## 5. Where the files go in each package

**cargo-packager 0.11.8 fields** (docs https://docs.rs/cargo-packager/latest/cargo_packager/config/struct.Config.html; behaviour read from the `0.11.8` crate source):

- **`license_file`** ("A path to the license file"). If unset, it falls back to the Cargo package's `license-file`, not its `license` (`src/cli/config.rs`). NSIS uses it as an installer licence page (`MUI_PAGE_LICENSE` in `src/package/nsis/installer.nsi`). The dmg passes it to `create-dmg --eula` (`src/package/dmg/mod.rs`), turning it into a click-through licence agreement shown when the image is mounted. WiX uses it too. The AppImage ignores it. It is a top-level field, so it cannot be set for NSIS only.
- **`copyright`** ("The app's copyright"). It becomes `NSHumanReadableCopyright` in the macOS `Info.plist` (`src/package/app/mod.rs`) and the NSIS `BrandingText` and `LegalCopyright` version key. The AppImage doesn't use it.
- **`resources`**. A list of globs or `{ src, target }` objects. For NSIS and WiX "the resources are placed next to the executable", for the macOS app bundle (and so the dmg) in `Contents/Resources` (`src/package/app/mod.rs`), and for the AppImage in `usr/lib/<main-binary-name>/` (`deb::generate_data`, reused by `src/package/appimage/mod.rs`). This is the one field that installs real files in every format used here.
- **`appimage.files`** maps a source file to any path inside the AppImage, for example `/usr/share/licenses/...` (`deb::copy_custom_files`).
- **`before-packaging-command`** / **`before-each-package-command`** are hooks that could run `cargo about generate` just before packaging.

**Recommended placement:**

- **Desktop (NSIS, dmg, AppImage).** Use `resources` to put `LICENSE`, `THIRD-PARTY-NOTICES.txt`, `assets/fonts/OFL.txt` (as `Archivo-OFL.txt`) and `assets/icons/LICENSE` (as `Lucide-LICENSE.txt`) under a `licenses/` target. They land in `<install dir>\licenses\` on Windows, `Personal Ledger Desktop.app/Contents/Resources/licenses/` in the dmg, and `usr/lib/desktop/licenses/` inside the AppImage. Set `copyright = "Copyright (c) 2024–2026 Ian Teda"`. Leave `license_file` unset for now: it would add a click-through EULA to the dmg (unusual for an MIT app) and might interfere with the CI step that runs `hdiutil attach -nobrowse -readonly` (§8). Shipping the licence as a file already meets MIT's "included in all copies".
- **TUI (AppImage, dmg).** Same `resources` mapping with `LICENSE` and `THIRD-PARTY-NOTICES.txt` (no fonts or icons), and the same `copyright`. Landing paths: `usr/lib/tui/licenses/` and `Personal Ledger TUI.app/Contents/Resources/licenses/`.
- **TUI Windows zip.** cargo-packager isn't involved, so the `Compress-Archive` step should add `LICENSE` and `THIRD-PARTY-NOTICES.txt` beside `personal-ledger-tui.exe`.
- **Sync Server image.** Remove `LICENSE*` from `.dockerignore`. Generate the notices in the builder stage. In the runtime stage, `COPY` `LICENSE` and `THIRD-PARTY-NOTICES.txt` to `/usr/share/doc/personal-ledger/`. Debian Policy §12.5 puts each package's licence at `/usr/share/doc/<package>/copyright` and says "Every package must be accompanied by a verbatim copy of its distribution license(s)" (https://www.debian.org/doc/debian-policy/ch-docs.html). The `debian:bookworm-slim` base already keeps its own packages' notices under `/usr/share/doc/*/copyright`, so one directory holds everything. `/usr/share/licenses/personal-ledger/` is the Arch and Fedora convention and would also work, but this research couldn't load those distributions' guidelines (§8). Also add `LABEL org.opencontainers.image.licenses="MIT"`, whose OCI definition is "License(s) under which contained software is distributed as an SPDX License Expression" (https://github.com/opencontainers/image-spec/blob/main/annotations.md).

## 6. Generated in CI or checked in

**Generate at build time, don't check the file in.** The notices file is a function of `Cargo.lock`, the target list and each crate's published licence files, so a checked-in copy goes stale on every dependency bump unless a drift check also runs. That is cargo-bundle-licenses' model, and it is the same work as generating. Generating where the package is built keeps the file exact for the build that ships it, and `--fail` turns an unknown licence into a failed build.

- **Desktop and TUI workflows.** Add a step before `cargo packager` on each OS job that installs cargo-about and runs `cargo about generate --fail --locked -c about.toml --manifest-path crates/bins/bin-<name>/Cargo.toml -o target/THIRD-PARTY-NOTICES.txt about.hbs`. `resources` then points at `../../../target/THIRD-PARTY-NOTICES.txt` (packager paths are crate-relative), or the hook commands run the same generation. Prebuilt archives cover the Linux x86_64, macOS arm64 and Windows x86_64 runners. Pin the version in `mise.toml` if a mise backend can install it (§8); otherwise download the pinned release archive and check its `.sha256`.
- **Sync Server Dockerfile.** Run cargo-about in the builder stage, so local `docker build` and CI produce the same image. Fetch the pinned `x86_64-unknown-linux-musl` or `aarch64-unknown-linux-musl` archive (both matrix architectures have one) and verify the checksum, or `cargo install --locked --features cli cargo-about@0.9.2` at the cost of about 1.5 minutes per build. `about.toml` and `about.hbs` must live outside `docs/` and must not match `*.md`, since `.dockerignore` drops both.
- **One config for all three.** Use a repo-root `about.toml` and a plain-text `about.hbs`. The template prints each licence once with its "Used by" crate list, and adds `crate.repository` so the MPL-2.0 entries carry their source location. One `targets` list covering all shipped platforms is simpler than one per package, and the cost is a few Windows-only crates (such as `dwrote`) appearing in the Linux notices, which over-includes harmlessly.
- **Keep the lists aligned.** `about.toml`'s `accepted` should hold the same set as `deny.toml`'s `allow`, so a licence that passes cargo-deny can also be rendered. A comment in each file pointing at the other is the minimum. A small check comparing the two sets, run with the lint, would catch divergence.
- **A local `mise run notices` task** that renders all three files lets anyone preview the output without CI.

## 7. Recommendation

1. **Generator: cargo-about `0.9.2`**, with a repo-root `about.toml`. Its `accepted` holds the `deny.toml` allow set ordered MIT first, then ISC, the no-attribution licences, BSD, Zlib, BSL-1.0, Apache-2.0, Unicode-3.0, CDLA-Permissive-2.0, MPL-2.0 and NCSA. Set `targets` to the shipped platforms, `ignore-build-dependencies = true`, `ignore-dev-dependencies = true`, `private = { ignore = true }` and `workarounds = ["ring", "rustls", "prost"]`. Add a plain-text `about.hbs` that includes each crate's repository URL. Install it with `--features cli` or from the pinned release archive.
2. **Generate per package at build time in CI** with `--fail --locked` (and in the Dockerfile builder stage for the image). Don't check the output in.
3. **Placement:** use cargo-packager `resources` → `licenses/{LICENSE, THIRD-PARTY-NOTICES.txt}` for Desktop and TUI, plus `Archivo-OFL.txt` and `Lucide-LICENSE.txt` for Desktop. Set `copyright = "Copyright (c) 2024–2026 Ian Teda"` in both packager tables, and leave `license_file` unset until the dmg EULA behaviour is checked. Add the two files to the TUI Windows zip. In the Sync Server image, put them at `/usr/share/doc/personal-ledger/{LICENSE, THIRD-PARTY-NOTICES.txt}` with `LABEL org.opencontainers.image.licenses="MIT"`, after dropping `LICENSE*` from `.dockerignore`.
4. **Duties this covers:** the MIT/ISC/BSD/Unicode-3.0/CDLA copyright-and-licence texts, the Apache-2.0 licence copies for the Apache-only crates, the MPL-2.0 source pointers for `option-ext` and `dwrote`, the OFL and Lucide notices for the embedded assets, and Personal Ledger's own MIT licence. There is no Apache NOTICE content today, but cargo-about would surface one if a crate starts shipping it.
5. **Optional later:** surface the notices in the apps themselves (for example a "Third-party licences" entry on the Desktop Help screen or a TUI popup reading the bundled file). Apache-2.0 §4(d) accepts "a display generated by the Derivative Works", but none of the duties above require it.

## 8. Unverified

- **dmg EULA in CI.** Whether a dmg built with `create-dmg --eula` blocks or prompts under the workflows' non-interactive `hdiutil attach -nobrowse -readonly` was not tested; that is why `license_file` is deferred. Also untested: how current macOS presents a dmg licence agreement.
- **Libraries bundled into the AppImages.** cargo-packager builds AppImages with linuxdeploy (`src/package/appimage/mod.rs`), which may copy system shared libraries (for example `libxkbcommon`, `libwayland-client`, `libfontconfig`, `libfreetype`) into the AppImage. Their licences (FreeType's FTL or GPL-2.0 choice, the LGPL for some, MIT for others) would add notice duties that cargo-about cannot see. The contents of the built Desktop and TUI AppImages were not listed.
- **Upstream NOTICE files.** The scan only checked the published `.crate` contents. Whether any upstream repository (for example Zed's for `gpui`) has a `NOTICE` that the published crate omits was not checked. Apache-2.0 §4(d) applies to "the Work" as distributed to us, so the published crate is the likely reference, but that reading is not confirmed.
- **Copyright lines for the 55 crates without licence files.** cargo-about falls back to the canonical licence text, without the author's copyright line. Whether to add `clarify` entries that pull the files from each crate's git repository (an online-only feature) was not evaluated crate by crate.
- **Installing cargo-about through mise.** It is not in mise's registry. Whether a `github:`/`ubi:` backend entry, or `"cargo:cargo-about" = { version = "0.9.2", features = "cli" }`, works with this repo's mise version was not tried. Nor was the missing `x86_64-apple-darwin` archive's impact on any Intel macOS runner (current `macos-latest` runners are arm64, but that was not confirmed for this repo's matrix).
- **`/usr/share/licenses/<package>/` convention.** The Arch and Fedora packaging guidelines pages returned bot-protection pages, so this convention is stated from general knowledge, not a primary source. Debian Policy §12.5 was confirmed.
- **`debian:bookworm-slim` doc handling.** That the slim image keeps `/usr/share/doc/*/copyright` (through a dpkg `path-include`) while dropping other docs was not checked in the image. It doesn't affect files added with `COPY`.
- **The CDLA-Permissive-2.0 reading.** That shipping the agreement's text in the notices file satisfies "makes available the text of this agreement with the shared Data" for CA roots compiled into the binary is a reasonable reading, not confirmed against CDLA guidance.
- **cargo-about in the Docker builder.** The trial ran on the host, not inside `rust:1.98.0-bookworm`, and did not test per-architecture output on arm64.
- **Graph drift.** All counts are from `Cargo.lock` at `2da7040` and will change with dependency updates. That drift is the reason for generating at build time.
