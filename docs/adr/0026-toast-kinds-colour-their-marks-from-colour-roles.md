# Toast Kinds colour their marks from Colour Roles

Toasts (see Toast and Toast Kind in `GLOSSARY.md`) come in four Toast Kinds: Info, Success, Warning and Error. Each kind needs its own colour so it can be told apart at a glance, but [ADR-0022](0022-seven-stored-colour-roles-with-calculated-shades.md) stores only seven Colour Roles, rejected a stored `warning`/`error`/`info` role, and says `negative` means only an amount.

We're colouring only the **non-text marks** of a Toast (its leading bar and its glyph) from existing Colour Roles: Info `foreground`, Success `positive`, Warning `accent`, Error `negative`. The border stays `muted` for every kind, and the text stays `foreground` on chrome. Each mark uses a calculated **mark shade**: the role, darkened or lightened until it reaches 3:1 against chrome, the surface a Toast sits on. Unit tests enforce this over every built-in Colour Theme and Colour Variant, and a failing `[theme]` override is corrected like the text shades. Each kind also carries a glyph, the same in both Clients, so no kind relies on colour alone: Info `i`, Success `✓`, Warning `!`, Error `✗` (U+2717, distinct from the Desktop's `✕` dismiss). In the TUI's terminal-colour fallback the marks are Info default colour, Success green, Warning and Error red, on a default-colour bordered box with a `BOLD` title.

This amends ADR-0022: `negative` marks a negative amount and the bar and glyph of an Error Toast, never text. Warnings still use `accent`, keeping the "one accent" rule.

## Considered options

New stored `info`/`success`/`warning`/`error` roles were rejected for the same reason as in ADR-0022: every Colour Theme and `[theme]` section would need four more values that the existing roles already express. Using `accent` for Error as well was rejected because Warning and Error would then differ only by glyph in every Colour Theme; with `negative` they differ in colour wherever a Colour Theme's `accent` and `negative` differ. Warning and Error are still both red in some Colour Themes (Modernist) and in the TUI fallback, which is accepted: the glyph is the required non-colour cue, and Error is also sticky. Colouring the border or the text by kind was rejected: a stack of Toasts should read as one calm system, and coloured text would need its own 4.5:1 shades on chrome. A `Color::Yellow` TUI fallback for Warning was rejected because the Colour Themes work had just removed the TUI's lone yellow.
