# A device's settings are Configuration in the conf file

ADR-0027 and ADR-0051 made Toasts, Colour Theme, Colour Appearance, date style and On start Client-scoped Preferences, kept by each Client in its own state file (`desktop-state.json`, `tui-state.json`) beside what it remembers for itself. A Client must run with no Ledger open on nothing but its own device's settings and built-in defaults, and those settings were then split between the conf file (Locale, `data`, `file`, `[theme]`, keybindings) and two state files, with `lib-config` already writing some of Settings › Display back to the conf file (#904).

We're making every setting that belongs to the device **Configuration**, kept in the `[Personal-Ledger]` section of the user's `personal-ledger.conf`: Toasts, Colour Theme, Colour Appearance, date style, On start and the new **Start view** (the View a Client lands on as it starts: `dashboard`, the default, `last`, `settings` or a noun; a View that needs a Ledger lands on the Dashboard's no Ledger open content when none is open). The user edits them by hand or from the This device Settings pages, which write the user's file through `lib-config` and say when an environment variable or a higher file shadows the key. Their scope does not change: they never sync, and they apply whichever Ledger is open or none. "Preference" now names only a Ledger-scoped setting, today the base Unit. The state files keep only what a Client remembers for itself (the last Ledger, window geometry, the last View and Settings page, the `:open` browser's filters, the Documents mode), never a choice the user made, and a missing state file starts the Client on defaults. Values already in the state files are not migrated.

This supersedes ADR-0027 and ADR-0051 on where these settings are stored, not on what they are or that they never sync.

## Considered options

Keeping them in each Client's state file was rejected: the user would customise one device in three places, and a state file the app rewrites at every quit is no place to hand-edit a choice. Moving the remembered state into the conf file too was rejected: the app would rewrite the user's hand-edited file at every quit. The cost accepted is that the Desktop and the TUI on one device now share these settings, so a Colour Theme chosen in one is the other's too, where each Client kept its own before.
