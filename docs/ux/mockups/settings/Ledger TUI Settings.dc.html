settingsSettings — database-backed

Settings live in the database, not a config file: every setting has a shipped default in code, and changing one writes a row to settings that overrides it. So a red dot means a row exists for this key — the dot is the override, and r deletes the row rather than writing the default back. Values edit in place (enter opens the row, ←→ picks an enum, esc reverts), commit in one transaction, and take effect on the next render — nothing to write, nothing to reload. Static config is reduced to the four bootstrap keys needed before the database is open. Settings that rewrite stored data (base unit) still route through a guard dialog.
