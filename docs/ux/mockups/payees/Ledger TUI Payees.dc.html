payeesPayees — list, new, edit, matches, delete

A payee is who the money moved to or from, and it is the one entity the user never deliberately creates — ADR-0012 auto-creates it the first time a name is typed on a transaction. So this is a curation screen, not a CRUD screen: its job is to fold the duplicates auto-creation produces back together and to teach each payee what it should default to. Three of the four things here — website, icon URL and default category — are not in the payees table yet and need a migration; rename matches are, as payee_aliases, but today they are only ever written by a rename. Renaming is never a plain field update: it keeps the old name as a match, in the same transaction, so 184 transactions show the new name at once without a single row being rewritten.

8aPayees. Sorted by what they cost, flagged where they need attention; the category mix is the evidence behind the default.
