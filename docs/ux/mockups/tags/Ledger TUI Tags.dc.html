tagsTags — a flat vocabulary, many per transaction

A tag is the second axis. A transaction carries exactly one category, and it may carry any number of tags — that many-per-row cardinality is the whole difference, and it makes two things true that the categories view never had to say. First, tag totals overlap: one transaction tagged twice is counted in both rows, so the column does not sum to spend and the screen must say so rather than inviting the addition. Second, there is no tree, no kind and no parent to inherit from — a tag is only a name, so every total on this screen is in one unit, stated once in the status line. A tag reaching a transaction in another unit cannot be folded in, and the count that was left out is shown rather than quietly dropped.
